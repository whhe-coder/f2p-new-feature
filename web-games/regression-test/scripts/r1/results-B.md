### 新发现

1. `/select-project` 在 c1b5e37 中没有注册路由：`src/routes/inside/select-project.js` 没有被任何文件 import（它 import 的 `@/app/pages/select-project`、`@reducers/projects/projects` 也是遗留路径），所以 `/{m}/select-project` 落到 `/not-found`。`src/layouts/Root.tsx:171,202` 仍按这个路径隐藏 sidebar 和 topbar。RT-UI-005 第 3 步和 RT-ROUTE-022 中有关 select-project 的预期需要改。
2. RT-SET-011 的预期写错：`/profile` 显示 “Back to account” 按钮（来自 SDK 的 ProfilePage，`src/routes.tsx:140-142` 注释说页面自带 back button），点击后 push 到 `/{m}`。T3 第 207 行和 475 行的 “没有 Back to account” 需要改；菜单项文案是 “Change profile”。
3. chargeback registry 页（`/analytics/main-info/afs/chargeback-registry`）上 Anti-fraud 带 `aria-current=page`，但 Analytics 组保持 `aria-expanded=false`，用户看不到高亮。原因：merchant 组的 `matchPaths` 只取 children 的 `to`（`src/layouts/sidebar/merchant-sidebar-v2/index.tsx:32`），不包含 `CHARGEBACK_REGISTRY_PATH`（`nav-items-config.tsx:207-208` 只作用在叶子上）。
4. 带 `utm_campaign` 打开 dashboard 时，每次加载发出 3 次相同的 `GET salescards/info`。原因：effect 依赖 `merchants?.length`、`projects?.length`，加载过程中这两个值会变化（`src/pages/Dashboard.tsx:97-121`）。
5. stage 上 `GET /mapi/merchant/current/merchants/53105/documents/url` 返回 500，Documents 页显示 “No documents found”（RT-ROUTE-019）。
6. stage 上 storefront remote（`/projects/317869/storefront/virtual-currency/packages`）加载 50 s 后仍是 Loading（RT-ROUTE-021 第 ② 步无法在 UI 上执行）。
7. 折叠态图标栏的 Tools 只读 store 的 `currentProjectID`（`src/layouts/sidebar/index.tsx:46` → `useProjectNavItems(intl, projectId)`）。展开态先取 URL 中的 id（`project-sidebar-v2/index.tsx:96-97`，即 PROJ-016 的修复）。项目解析完成前（dashboard 加载约 1.5 s 时）折叠栏只有 “Other tools”（Marketplace / Ontology），项目工具组都不出现；约 15 s 后才正常。PROJ-016 的修复没有覆盖折叠态。
8. 错误页按钮文案为 “Go to homepage”，`UIMLink to="/"` 渲染出的 href 是 `{base}/`（不带 merchant），由默认重定向到 `/{m}`（RT-NAV-030 写的是 “To homepage”、按钮到 `/{m}`）。
9. 执行环境问题：用 `window.open(..., 'noopener,noreferrer')` 打开的 tab（横幅按钮）在 CDP 连接的 Chromium 中停在空 URL，并让所有 `connectOverCDP` 卡住（对另一个 agent 也有影响），直到用 `/json/close` 关闭。之后测外链 noopener 时，脚本要主动关闭新 target。
